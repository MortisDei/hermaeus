# Media generation

The Media page generates images, audio or video through an explicitly configured
endpoint. This is separate from Chat image attachments, microphone transcription
and read-aloud. A model appearing in a chat model list is not evidence that it
can generate media.

## Local models through ComfyUI

Hermaeus is an API client for a user-managed ComfyUI server. It does not install
or launch ComfyUI, Python, custom nodes or model weights. Configure its URL,
optional bearer key and enable switch under **Services > Media generation /
ComfyUI**. Invalid configuration reports a failed save and preserves committed
settings; Services confirms only a successful save. The ordinary settings save
flow stores a key reference in settings;
leaving the key field empty retains an existing stored key.

1. Prepare and test a trusted workflow in your ComfyUI server with its required
   model, text encoder, VAE/vocoder and nodes installed.
2. Export that workflow in **API format**, not the editor's normal save format.
3. Open **Media**, select **ComfyUi** and the output kind. Load or paste the API
   JSON. Set the intended string input value to exactly `{{prompt}}`.
4. Enter your prompt and choose **Generate**. Hermaeus substitutes that exact
   string input as a JSON value, submits once, polls the returned job's history
   and retrieves saved outputs of the selected kind.
5. Select an output and **Export selected file** to keep it. Images get a bounded
   preview. Export audio/video to open them in your preferred player.

The workflow owns model choice, negative prompts, seeds, sampling, dimensions,
duration and output nodes. Only direct string values under a node's `inputs`
are substituted; substrings, node names and class types are not rewritten.
Saved image, audio and video output records are supported, including video files
reported under ComfyUI's image/GIF output groups. Temporary/input files and
unsafe paths are refused. Custom output schemas need a matching adapter before
Hermaeus can consume them.
Supported container signatures are PNG/JPEG/WebP/GIF, WAV/FLAC/MP3/Ogg (including
Opus), and MP4/WebM. Ogg output is exported with an `.ogg` extension.

Workflows execute the backend's installed nodes. A loopback address does not
make arbitrary custom nodes safe or prevent those nodes making network calls.
Only submit workflows you trust. Hermaeus does not send a global interrupt or
clear a shared queue.

## Remote and OpenAI-compatible providers

Configure and enable the existing **Settings > LLM > OpenAI / Compatible API**
endpoint and credential. In Media, choose **OpenAiCompatible**, output kind and
the exact generation model ID. This path also works with a local server that
implements the selected media protocol, without requiring an API key if that
server does not need one.

| Kind | Required protocol | Options |
| --- | --- | --- |
| Image | `POST /v1/images/generations` | Prompt, model, one requested output, optional size |
| Audio | Audio-output `POST /v1/chat/completions` | Prompt, model, voice; requests non-streamed WAV output |
| Video | `POST /v1/videos`, per-job status and content endpoints | Prompt, model, duration and optional size; asynchronous polling |

The base URL may already end in `/v1`, including a path prefix. Provider-specific
model access and accepted sizes/durations/voices still apply. Ordinary text-only
chat compatibility is insufficient. Audio-output chat is distinct from the
existing speech-synthesis provider; a TTS-only model is not interchangeable.
No automatic paid capability probes, fallback model calls or job resubmissions
are made. Unsupported protocols, rejected requests and malformed outputs fail
visibly. Endpoint access and model inference have not been proven by mock HTTP
fixtures.

Image responses must contain base64 bytes or a URL at the configured origin.
Cross-origin URL-only responses, including legacy provider CDN responses, are
refused. Use a provider/model returning inline image data. Redirects are not
followed, and credentials are per-request rather than shared default headers.

## Limits, cancellation and export

- At most eight output files and 128 MiB of retained generated bytes per
  operation. JSON/base64 generation responses have an additional 48 MiB wire
  limit; control responses have a 2 MiB limit. Actual reads and combined decoded
  payloads are counted, including absent or false Content-Length headers.
- Prompts are limited to 32,768 .NET characters. Workflow file import is at most
  1 MiB of strict UTF-8; pasted workflow JSON is at most 1 Mi characters, 1,024
  nodes and JSON depth 64. Expanded escaped UTF-8 workflow requests are bounded
  to 8 MiB, including a reserved allowance for the submission envelope.
- Generation operations have a 30-minute cancellation deadline and finite polling.
  This does not bound backend inference, total process memory or synchronous
  parser/codec work. Encoded JSON, decoding and preview can use extra memory.
- **Cancel waiting** stops client requests/polling and refuses late results.
  An accepted server job may still run, charge and save backend output. The job
  ID stays visible for investigation in that provider. Do not assume cancelling
  locally deleted or cancelled a remote job.
- Recognised container signatures determine output extensions; they do not prove
  that every frame/sample is decodable. Image preview refuses dimensions above
  16,384 on either axis or 32 million pixels, and scales to at most 1,024 on its
  longer side. Preview failure leaves original bytes available for export.
- Results remain in memory for this app session. Clear/exit drops session
  references; it is not secure memory erasure. Results and prompts are not added
  to conversation history, Agent state, activity traces or a new media database.
  A previous successful result remains available when a later generation fails.
- Shutdown cancels the client's wait for workflow/export pickers and ignores
  late selections. Native dialog dismissal remains the platform owner's job.
  Only the current view owns picker results and decodes new image previews.
- Export requires an explicit local file selection with the matching extension.
  It writes a sibling staging file and atomically replaces the selected target.
  Unix creation requests mode 0600; Windows uses normal directory ACL inheritance.
  Reparse ancestors are refused. These metadata checks do not guarantee atomic
  filesystem identity against hostile live swaps. Nothing is autoplayed or
  automatically launched by exporting it.
  If export and staging-file deletion both fail, both causes are preserved as
  an export failure. A deletion failure can leave the private staging file in
  the selected directory; it is not reported as a successful export or clean
  cancellation.

Privacy Audit discloses the media surface and counts enabled non-loopback or
invalid ComfyUI endpoint configuration conservatively as outbound. Prompts,
workflow JSON, credentials, raw provider error bodies and media bytes are not
written to runtime logs by the media client. Backend storage/retention and any
backend custom-node traffic remain controlled by that backend.

## Local model candidates

The repository's R34 review pack records dated research and hardware limits.
[ACE-Step 1.5](https://huggingface.co/ACE-Step/Ace-Step1.5) is a music candidate;
FLUX.2 klein, Wan and LTX candidates need exact precision,
companion, runtime and memory validation. No model is certified to fit the
6 GB desktop or 8 GB laptop merely because its weights are small. Keep memory
headroom for other loaded models. This feature does not install a new runtime or
claim local model performance or quality.
