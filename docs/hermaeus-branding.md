# Hermaeus brand specification

This document is the source of truth for Hermaeus's product-level visual
language. [`mascot.md`](mascot.md) is the source of truth for Moss's identity,
voice, and in-app character use.

## Goal

Hermaeus should feel like a premium local-first AI workspace that communicates
knowledge, trust, craftsmanship, privacy, and quiet confidence.

It should not present itself as magic, science fiction, gaming software, or an
oracle. Branding supports the product's usability and transparency; it does not
compete with them.

## Visual language

Primary references are libraries, manuscripts, archives, botanical collections,
natural materials, and high-quality native desktop software. Prefer calm
surfaces, readable hierarchy, restrained accents, and simple geometry.

Avoid eyes, crystals, shields, swords, fantasy crests, and generic AI symbols.
Avoid gradients when a flat treatment communicates the same thing.

## Typography

The default is the operating system's native UI typography. The current
defaults are `Segoe UI,sans-serif` for headings and body text and
`Consolas,monospace` for code and technical text. Settings > Interface >
Typography lets the user override those three roles independently.

Do not bundle fonts or add a rendering dependency for branding. Readability,
accessibility, native appearance, and low maintenance take priority over a
fixed typeface.

## Logo and application icon

The mark should have a recognisable silhouette, work in monochrome, remain
legible at 16x16, and use simple geometry. Suitable motifs include the
Archivist's seal, tree rings, an open book, branches, roots, growth rings, and
an abstract H. It should not depend on gradients.

The shipped application, taskbar, desktop, and tray icons use the Moss
icon-scale geometry. The raster assets are generated by
[`scripts/generate-icons.ps1`](../scripts/generate-icons.ps1) from the same
geometry used by `Controls/MossIcon.axaml`. See [`mascot.md`](mascot.md) for
the character and icon details.

## Moss

Moss represents accumulated knowledge and patient guidance. He is not comic
relief and is not the model doing the reasoning. His identity, UI voice,
appearance, and approved placements are defined in [`mascot.md`](mascot.md).

## Interface

Priorities are readability, consistency, performance, and a native desktop
feel. Use branding to clarify hierarchy and state, never to obscure an error,
delay a decision, or imply capabilities the application has not verified.

The intended impression is software maintained by an experienced archivist.
